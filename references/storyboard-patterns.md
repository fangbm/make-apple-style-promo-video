# Storyboard Patterns

## 30-Second Software Product Pattern

| Time | Purpose | Recommended content |
| --- | --- | --- |
| 0-4 s | Identify | Logo, product name, literal category/value statement |
| 4-11 s | Prove primary value | One realistic task, cursor travel, target highlight, anchored result |
| 11-18 s | Show control | Selection, menu, second mode, or user-triggered workflow |
| 18-24 s | Broaden context | PDF, mobile, dashboard, desktop, or another supported surface |
| 24-27 s | Summarize system | Three short proof points or a compact pipeline |
| 27-31 s | Resolve | Dark end card, logo, name, tagline, platforms/CTA |

## 15-Second Store Preview Pattern

1. `0-2s`: product and category.
2. `2-8s`: one complete interaction.
3. `8-12s`: second state or result.
4. `12-15s`: end card.

Remove exposition before reducing reading time. Keep the main interaction complete.

## 45-Second Feature Reel Pattern

Use no more than four feature scenes. Add duration to settled states and transitions rather than adding six more features. Reserve 4-6 seconds for the final brand resolution.

## Copy Formula

Use this hierarchy:

1. **Category/value:** literal and concise. Example: “Understand technical terms without leaving the page.”
2. **Scene headline:** state the user outcome, not the implementation.
3. **Scene support:** one sentence explaining what just happened.
4. **UI copy:** authentic product labels.

Avoid “revolutionary,” “magical,” “next-generation,” and unsupported superlatives. Show proof instead.

## Scene Density Test

At the settled frame, ask:

- Can a viewer identify the product action within one second?
- Is there exactly one primary focal point?
- Is the relevant UI large enough at half-size?
- Does the secondary content support the feature rather than fill space?
- Can the viewer read the scene before it exits?

If a scene is empty, add meaningful structure such as a step number and a three-stage flow. If a scene is busy, remove browser details, prose, or simultaneous motion.

## Timing Notation

Write each event as data before implementation:

```text
05.20 highlight begins
05.70 cursor travels
06.80 cursor settles
07.20 card opens
07.90 card settles
09.60 scene begins exit
```

Keep these timestamps in one source of truth. Audio cue times should reference the same list.
